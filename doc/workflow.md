# Workflow

Use GitHub Issues only for durable work tracking.

## When to use GitHub Issues

- File bugs, feature requests, follow-up work, accepted TODOs, and security-audit findings as GitHub Issues.
- Keep implementation notes, review notes, QA outcomes, and completion evidence in the related GitHub Issue or PR description.
- Keep durable product and engineering decisions in `doc/`, then link them from related GitHub Issues.

## What not to store in repo

- Do not create repo-local work queues or workflow lane directories.
- Do not use Markdown files in the repo as durable work queues unless explicitly part of product or engineering documentation.

## Closing work

Before closing an issue, confirm linked code, docs, tests, manual checks, and follow-up issues are recorded in GitHub.
