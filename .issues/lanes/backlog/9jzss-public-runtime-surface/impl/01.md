# 01 — Narrow root runtime exports

## Source
- plan/01-implementation-plan.md

## Goal
Remove accidental runtime-internal named exports from the package root while preserving the intentional stable DSL, app, adapter, extension, and error/result contracts.

## Depends on
- none

## Scope
- `src/index.ts`
- `src/__tests__/type-check.ts`
- internal tests only if typecheck reveals they accidentally import removed internals from the root

## Contract surfaces
- TypeScript module API for the `esther` root export surface
- public error/detail contracts: `BoundaryObservation`, `BoundaryObservationError`, `SliceError`
- extension contracts for adapters, stores, read models, processors, and typed route bindings
- deprecated read-model compatibility exports: `ProjectionAdapterEntry`, `ProjectionAdapterTableEntry`, `ProjectionAdapterViewEntry`, `projectionAdapters`, `projectionQuery`

## Plan-check watch items
- Verify the generated/type-visible root API does not accidentally require consumers to name `ReadInterpreter`, `ProjectionStore`, `SliceDeps`, `Step`, or other removed internals through exported signatures.
- If `compose` array-form or `Processor` declaration leakage makes removed internals practically visible, do not redesign opacity in this issue; record a focused follow-up unless typecheck forces a small local fix.
- Keep `BoundaryObservation` and `BoundaryObservationError` root-public and preserve type-check coverage because they are observable error/detail contracts.
- Keep deprecated `ProjectionAdapterEntry`, `ProjectionAdapterTableEntry`, `ProjectionAdapterViewEntry`, `projectionAdapters`, and `projectionQuery` compatibility unless a separate removal issue/release decision is made.
- Prefer negative API checks for removed exports, but if TypeScript import-error assertions prove brittle, use a targeted source/export inspection check as planned.

## Work
- Update `src/__tests__/type-check.ts` first so it no longer imports or uses `SliceDeps` from the root.
- Preserve positive type-check coverage for `BoundaryObservation`, `BoundaryObservationError`, `SliceError`, read-model registration types, adapter extension contracts, and operation helper types.
- Add focused negative API coverage for at least one or two removed root exports, such as `executeCommand` and `ProjectionStore`, if this can be done without brittle TypeScript import-error behavior.
- If negative import assertions are brittle, add or document a targeted source/export inspection check instead.
- Update `src/index.ts` to remove named root exports for `executeCommand`, `executeQuery`, `createReadInterpreter`, `ReadInterpreter`, `ReadInterpreterDeps`, `ProjectionStore`, `SliceDeps`, `CompileDeps`, `CompiledOperation`, `Step`, `StepError`, and `InlineResult`.
- Keep stable DSL/app exports, adapter constructors, extension contracts, event/error/result contracts, read-model DSL, processor/effect DSL, operation helper types, and deprecated compatibility types root-public.
- Do not delete, rename, or behaviorally change internal modules such as `src/core/pipeline.ts`, `src/core/read-interpreter.ts`, or `src/core/slice.ts`.
- If declarations still leak a removed internal type in a way that blocks typecheck, make the smallest local fix needed or stop and record a follow-up for opaque descriptor/operation types.

- Root-public stable DSL/app, adapter constructor, extension contract, event/error/result, read-model DSL, processor/effect DSL, operation helper, and deprecated compatibility exports still typecheck.
- `src/__tests__/type-check.ts` no longer treats `SliceDeps` or executor/interpreter internals as root-public API.
- No command/query execution, event append, read-model query, processor, adapter, persistence, migration, replay, auth, or side-effect behavior is changed.
- Any retained watch-item export is explicitly justified in `impl/checkpoints/01.md`.
