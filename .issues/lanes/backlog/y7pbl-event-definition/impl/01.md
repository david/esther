# 01 — Add event definition core helper

## Source
- plan/01-implementation-plan.md

## Goal
Add core `defineEvent(...)` contract with generated schema, constructor, derived types, root exports, and event-type extraction owned by event module.

## Depends on
- none

## Scope
- `src/core/event.ts`
- `src/core/event.test.ts`
- `src/core/processor.ts`
- `src/core/app.ts`
- `src/index.ts`

## Contract surfaces
- public core DSL: `defineEvent`, `EventDefinition`, `EventOf`, `EventPayloadOf`
- generated Zod event schema: `{ type, tags, payload }`
- event constructor: `.create({ tags, payload })`
- event type extraction helper used by processor/read-model wiring
- root package export surface

## Plan-check watch items
- Keep direct `EventDefinition` acceptance in reducer/read-model/processor APIs out of this slice; users must pass `.schema`.
- Ensure generated `.schema` remains a real `z.ZodObject` with literal `type`, not wrapped by transform/refine that breaks `extractEventType`.
- If `schema` typing needs a cast, keep it as narrow as possible inside `src/core/event.ts` and document why.
- Preserve `extractEventType` direct module compatibility from `src/core/processor.ts` if tests/imports rely on it.
- Verify `.create(...)` copies `tags` and keeps payload reference caller-owned.

## Work
- Add focused failing tests in `src/core/event.test.ts` for `defineEvent(...).type`, `.payloadSchema`, `.schema.parse(...)`, `.schema.safeParse(...)` wrong type rejection, `.create(...)` shape, defensive tag copy, and payload reference preservation.
- Create `src/core/event.ts` with `EventDefinition`, `EventOf`, `EventPayloadOf`, `defineEvent`, and `extractEventType`.
- Generate `.schema` with `z.object({ type: z.literal(definition.type), tags: z.array(z.string()), payload: definition.payload })`.
- Implement `.create(...)` as object construction only; do not call `.parse`, `.safeParse`, or other validation.
- Move or delegate `extractEventType` ownership to `src/core/event.ts`.
- Update `src/core/processor.ts` to import `extractEventType` from event module and re-export it if existing direct imports/tests need compatibility.
- Update `src/core/app.ts` to import `extractEventType` from event module.
- Add package root exports in `src/index.ts` for helper and types.
- Keep any unavoidable cast local to `src/core/event.ts` with comment explaining Zod generic output constraint.

## Acceptance
- `defineEvent`, `EventDefinition`, `EventOf`, and `EventPayloadOf` are exported from package root.
- Event definition exposes `type`, `payloadSchema`, `schema`, and `create`.
- Generated schema validates the same serialized event shape `{ type, tags, payload }`.
- Wrong event type literal fails schema validation.
- `.create(...)` returns `{ type, tags, payload }`, copies tags, keeps payload reference caller-owned, and does not parse.
- `extractEventType` still works for generated and existing raw `z.object` schemas.
- Processor module direct `extractEventType` compatibility remains if current tests/imports rely on it.
