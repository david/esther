# 01 — Preserve operation name literals

> Superseded: do not implement this task without replanning. The prior `app.client.dispatch(...)` direction conflicts with the intended adapter-boundary invocation model.

## Goal

Make registered command and query definitions retain their literal `name` types and expose enough type information for a later typed app client to map a slice name to that slice's input, output, and error contract. Keep all existing public annotations source-compatible through generic defaults.

## Depends on
- none

## Scope
- `src/core/slice.ts`
- `src/__tests__/type-check.ts`
- `src/index.ts` only if newly introduced public helper types are intentionally exported from slice/core in this slice

## Contract surfaces
- `RegisterableOperation` type shape and generic defaults
- `Command` and `Query` generic signatures and defaults
- `defineCommand` and `defineQuery` type inference for `definition.name`
- public type exports, only for helper types needed by the planned app client
- runtime execution semantics: unchanged

## Plan-check watch items
- Keep `App`, `AppConfig`, `RegisterableOperation`, `Command`, and `Query` generic defaults source-compatible for existing consumers.
- Confirm `defineCommand` / `defineQuery` infer literal `name` types without forcing `as const` at every call site.
- Ensure the eventual typed client can include framework `SliceError` plus the operation-specific error type.

## Work
- Add or update compile-only assertions in `src/__tests__/type-check.ts` that fail before the type changes: a named command exposes the literal name `"create-booking"`, a named query exposes the literal name `"get-pricing"`, and assigning either to an unrelated literal is a `@ts-expect-error`.
- Update `RegisterableOperation`, `Command`, and `Query` in `src/core/slice.ts` to preserve `TName extends string` with source-compatible defaults.
- Update `CommandDefinition`, `defineCommand`, and `defineQuery` signatures so inline `name: "..."` values are inferred as literals without requiring `as const` at call sites.
- Add small type helpers only if they are needed to represent operation name/input/output/error extraction for the app client; keep helper names cohesive and avoid broad conditional-type complexity.
- Preserve `CompiledOperation` and the runtime `compile(...).execute(...)` behavior as the existing dynamic execution boundary.
- Update public exports in `src/index.ts` only for helper types that are part of the intended public typed-client contract.
- Run the focused typecheck while iterating, then the required verification commands.

## Acceptance
- `defineCommand({ name: "create-booking", ... })` retains `"create-booking"` in the returned command type without `as const`.
- `defineQuery({ name: "get-pricing", ... })` retains `"get-pricing"` in the returned query type without `as const`.
- Existing code that imports or annotates `RegisterableOperation`, `Command`, or `Query` without new generic parameters remains source-compatible.
- No command/query runtime behavior, event behavior, read-model behavior, processor behavior, or adapter dispatch behavior changes.
