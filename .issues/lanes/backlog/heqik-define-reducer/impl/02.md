# 02 — Cut over reducer-only query contracts

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal
Switch every production event-history query contract from raw `schemas + fold` to `ReducerDefinition`, updating adapters and existing call sites together so the repo keeps one coherent contract.

## Depends on
- 01.md

## Scope
- `src/core/event-store.ts`
- `src/core/slice.ts`
- `src/core/read-model.ts`
- `src/core/read-interpreter.ts`
- `src/adapters/in-memory/event-store.ts`
- `src/adapters/filesystem/index.ts`
- `src/adapters/postgres/index.ts`
- existing tests and fixtures that must be mechanically converted to compile with the reducer-only contract

## Contract surfaces
- `EventStore.queryByTags(tags, reducer)` replaces `(tags, schemas, fold)`
- `tagQuery({ key, tags, reducer })` replaces raw fields
- `castTagQuery({ key, cast, tags, reducer })` replaces raw fields and removes subject-aware fold
- `eventsByTagsDescriptor(tags, reducer)` replaces raw args
- adapters parse with `reducer.schemas` and fold with `reducer.fold`
- command/query boundary observations still use call-site tags

## Plan-check watch items
- Convert every public raw event-history read surface together; partial conversion should fail typecheck.
- Preserve `castTagQuery` absent handling, schema-error behavior, `${key}Subject`, and boundary observation tests while removing subject-aware fold.
- Watch existing `schemas: []` tests; replace with reducer definitions without widening event/state types or introducing unsafe casts.
- Keep core/adapters dependency direction intact: core reducer module must not import adapters.
- Do not add `object`, explicit `any`, or `Record<string, unknown>` while repairing mapped-key/type accumulation issues.

## Work
- Update `EventStore` interface to accept a `ReducerDefinition` parameter.
- Update in-memory, filesystem, and Postgres event-store implementations to parse matching events through `reducer.schemas` and return `reducer.fold(parsedEvents)`.
- Update `tagQuery` descriptor/input-step/query-step types and runtime execution to store and forward `reducer` instead of `schemas` and `fold`.
- Update `castTagQuery` descriptor types and runtime execution to forward `reducer`; keep cast lookup, absent/error handling, computed `${key}Subject`, and boundary observation behavior.
- Update `eventsByTagsDescriptor` and read interpreter to store and forward `reducer`.
- Mechanically convert existing production/test call sites to local `defineReducer(...)` values so the repo compiles under the new contract.
- Remove production overloads/types/comments that expose public raw `schemas + fold` forms.

## Acceptance
- Production code exposes reducer-only contracts on `tagQuery`, `castTagQuery`, `eventsByTagsDescriptor`, and `EventStore.queryByTags`.
- Event-store adapters all consume `reducer.schemas` and `reducer.fold`.
- `castTagQuery` no longer accepts or calls a subject-aware fold; subject remains available as `${key}Subject`.
- Existing call sites compile after conversion to reducer definitions.
- No adapter imports another adapter and core imports no adapter code.
