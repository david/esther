## Source

## Goal

Create `doc/dcb.md` as the canonical short guide that teaches Esther DCB in minutes: command-side event-history reads observe one tag boundary, then append uses an optimistic guard for that boundary.

## Scope

## Plan-check watch items
- Keep `doc/dcb.md` concise; avoid large tutorial/sample app creep.
- Ensure snippets use current public API names and compile mentally against `defineEvent`, `defineReducer`, `defineCommand`, `compose`, `tagQuery`, `castTagQuery`, `lookup`, `generate`.
- In examples, emitted event tags should include same decision boundary tag when event can affect future decisions.
- State tag intersection semantics near first `tagQuery(...)` example, not only in limits section.
- Include projection-only misuse and missing-emitted-boundary-tag misuse; both map to current common failure modes.

## Work
- Add `doc/dcb.md` with one short guide, not a large tutorial or sample app.
- Start with the mental model: DCB = lock what command-side event-history read observed, using tags, through optimistic append precondition.
- Include Esther flow from tag query to append guard: `tagQuery`/`castTagQuery` -> `eventStore.queryByTags` -> state + max position -> command validates -> append with `{ boundaryTags, expectedPosition }` -> possible `ConcurrencyError`.
- Explain `observedBoundary`, `appendGuard`, `decisionTags`, `projectionContext`, `futureVisibilityTags`, and `singleBoundaryLimit` using visible headings or bullets.
- Add a small correct example, preferably account withdraw or username claim, using current API names and one decision boundary tag.
- Put tag intersection semantics next to the first `tagQuery(...)` example: event must contain every queried tag.
- Add a compact decision checklist: what prior events could invalidate this decision, what tag set includes them, did command read that tag set, will emitted event be visible to future reads.
- Add common misuses: projection-only `lookup(...)` before append, too-narrow intersection tags, emitted event missing boundary tag.
- Add current limits: one observed command boundary, no emitted-tag verification, `[]`/`undefined` means global stream, DCB is not authorization, query/projector/processor reads do not create command append guards.
