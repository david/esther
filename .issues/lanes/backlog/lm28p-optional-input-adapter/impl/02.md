# 02 — Preserve adapter-bound lifecycle behavior

## Source
- plan/01-implementation-plan.md

## Goal
Prove existing adapter-bound apps still bind during `createApp()` and still delegate lifecycle calls exactly once.

## Depends on
- 01.md

## Scope
- `src/core/app.ts`
- `src/core/app.test.ts` or closest core app test location
- `src/__tests__/type-check.ts`

## Contract surfaces
- `InputAdapterBinding` remains unchanged.
- `DispatchFn` remains `(sliceName: string, input: unknown) => Promise<Result<unknown, unknown>>`.
- Adapter `bind(dispatch)` still runs exactly once during app creation when `inputAdapter` exists.
- Adapter `adapter.start()` and `adapter.stop()` still run from `app.start()` / `app.stop()` when `inputAdapter` exists.

## Plan-check watch items
- When asserting adapter-present path, ensure test proves `bind` happens during `createApp()` and lifecycle methods are called once.
- Existing config with `inputAdapter: createInMemoryAdapter()` must still type-check.
- Keep implementation localized to `src/core/app.ts` unless tests reveal real need.
- Use optional guard/chaining without casts, `Record<string, unknown>`, or new loose object shapes.

## Acceptance
- Adapter-present `createApp()` calls `inputAdapter.bind(dispatch)` exactly once during construction.
- Adapter-present `app.start()` delegates to `inputAdapter.adapter.start()` exactly once per call.
- Adapter-present `app.stop()` delegates to `inputAdapter.adapter.stop()` exactly once per call.
- Existing adapter-bound app type examples still compile.
- No input adapter contract or concrete adapter implementation changes are required.
