# 01 — Document intentional command/query DSL split

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Make public guidance explicitly say `compose<T>().add(...)` and `state<T>().pipe(...)` are intentionally separate current public concepts because command input pipelines can affect DCB append preconditions while query state resolvers are read-only.

## Depends on
- none

## Scope
- `doc/domain-language.md` command/query terminology and rationale
- `llms.txt` canonical guidance and examples
- `doc/architecture.md` only if a short cross-reference helps avoid duplicated detail
- no runtime/API files unless a public example contradiction is found

## Contract surfaces
- public documentation contract for command input pipeline vs query state resolver
- public LLM guidance in `llms.txt`
- no event, schema, auth, persistence, read-model, adapter, processor, or runtime TypeScript signature changes

## Plan-check watch items
- Keep implementation docs-only unless a public example contradiction is found.
- Ensure `doc/domain-language.md` explicitly says current split is intentional, not accidental.
- Ensure `llms.txt` stays aligned with examples and includes short rationale for distinct names.
- Avoid new aliases: no `compose().pipe(...)`, `state().add(...)`, or shared public builder.
- If runtime/type files change, add focused type/runtime tests before full gates.
- Avoid overstating future design: current decision, future convergence requires separate migration/type-compat plan.

## Work
- Update docs first; no failing runtime test is needed because this is docs-only and behavior remains unchanged.
- In `doc/domain-language.md`, add compact rationale near command input pipeline and query state resolver sections explaining why current public names differ.
- In `llms.txt`, add high-signal guidance that command examples keep `compose().add(...)`, query examples keep `state().pipe(...)`, and shared helpers do not mean shared operation semantics.
- Optionally add one sentence in `doc/architecture.md` pointing readers to the domain-language distinction if existing execution-model text needs that bridge.
- Keep wording scoped to current decision; do not imply future convergence is impossible.
- Do not add aliases, shared public builders, runtime changes, or TypeScript public signature changes.
- If any runtime/type file changes unexpectedly, add or update focused type-check/runtime coverage before full gates.
