# 02 — Validate definition-backed events before append

## Source
- plan/01-implementation-plan.md

## Goal
Use event-definition schema metadata from `defineCommand` to validate constructed command events after command validation and before append. Return `SchemaError` on malformed definition-backed events without storing events or running downstream projectors, read-model bindings, processors, or effects.

## Depends on
- 01.md

## Scope
- `src/core/pipeline.ts`
- `src/core/slice.ts` if command metadata shape needs adjustment
- `src/__tests__/pipeline-wiring.test.ts` or another focused core pipeline test

## Contract surfaces
- command runtime validation ordering
- `SchemaError("Event validation failed", issues)` framework error path
- event store append boundary and DCB append options
- read-model projector/event-binding fanout via `onAfterInsert`
- processor/effect fanout via `onAfterCommit`
- raw command event path remains unvalidated

## Plan-check watch items
- Decide and document exact parsed-event behavior before merging implementation: append original event vs parsed event from `EventDefinition.schema.safeParse(...)`. This matters if Zod transforms are ever used in payload schemas.
- Runtime tests should assert append never called or event store remains unchanged, plus no hook/effect counters changed.
- Keep event validation failure in pipeline framework-error path; do not route it through `outputErr`.

## Work
- Add focused failing runtime tests first:
  - event-definition-backed command with casted malformed payload returns `Err(SchemaError)`.
  - event store remains unchanged after failure; if using append wrapper, assert `append` was not called.
  - read-model projector/event-binding counter remains `0`.
  - processor/effect counter remains `0`.
  - valid event-definition-backed command appends and `output` receives typed event.
  - raw command path can still append malformed payload when caller deliberately uses raw interop form.
- In `executeCommand`, after `slice.event(ctx)` and before append options/append, run optional command event schema validation.
- On validation failure, return `err(SchemaError("Event validation failed", issue details))` directly.
- Choose parsed-vs-original append behavior; prefer parsed event if transforms are allowed, and record choice in checkpoint.
- Ensure append options from boundary observations are unchanged for validated events.
- Ensure framework errors still bypass `outputErr`.

## Acceptance
- Malformed definition-backed command event returns `SchemaError` before append.
- Failed validation stores no event and triggers no projectors, read-model event bindings, processors, or effects.
- Valid definition-backed command appends same stored event shape as before.
- Raw command event form remains supported and intentionally unvalidated by event definition.
- Validation ordering remains: input parse → input pipeline → boundary observation check → command validation → event build → event schema validation → append → output.
