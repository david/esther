# 05 — Dispatch transform candidates as parsed events

## Source
- plan/03-transform-schema-command-event-contract-plan.md

## Goal
Prove and preserve runtime ordering for definition-backed transform payload schemas: dispatch builds a schema-input candidate, validates it with `EventDefinition.schema`, appends only the parsed output event, and passes that parsed event to `output(event, ctx)`.

## Depends on
- 04.md

- `src/core/slice.ts` if candidate metadata or event schema typing needs adjustment after task 04
- `src/__tests__/pipeline-wiring.test.ts` or another focused core pipeline test

## Contract surfaces
- dispatch event validation ordering
- event store append value
- `output(event, ctx)` runtime value
- `SchemaError("Event validation failed", issues)` framework-error path
- read-model/projector/processor/effect fanout after append
- raw command path remains unvalidated

## Intent / decision vocabulary
- `CommandEventCandidate`: runtime candidate produced by `slice.event(ctx)` before schema parse
- `ParsedCommandEvent`: only value appended and passed to `output(event, ctx)` after successful schema parse
- `RawInteropEvent`: raw command event path with no event-definition validation
- invariant: downstream work happens only after successful append
