# 02 — Add typed app client dispatch

> Superseded: do not implement this task without replanning. The public in-process `app.client.dispatch(...)` facade conflicts with the intended adapter-boundary invocation model.

## Goal

Add the additive `app.client.dispatch(name, input)` in-process typed facade over the existing app dispatch path, while leaving `app.dispatch(sliceName: string, input: unknown)` and input adapter binding dynamic and behavior-compatible.

## Contract surfaces
- `AppConfig<TSlices>` generic app configuration, with defaults preserving existing source compatibility
- `App<TSlices>` public app type, with defaults preserving existing source compatibility
- new `AppClient<TSlices>` public typed in-process client
- `app.client.dispatch(...)` typed name/input/result contract
- existing `app.dispatch(...)` dynamic in-process/transport contract: unchanged
- `InputAdapterBinding.bind(dispatch)` receives the existing dynamic dispatch function: unchanged
- runtime validation remains owned by existing slice input/output schemas

## Plan-check watch items
- Keep `App`, `AppConfig`, `RegisterableOperation`, `Command`, and `Query` generic defaults source-compatible for existing consumers.
- Ensure `app.client.dispatch` result errors include framework `SliceError` plus the operation-specific error type.
- Keep the dynamic-to-typed bridge local and documented if a cast is necessary.
- Add `@ts-expect-error` cases that prove typed dispatch rejects unknown names and invalid input, while dynamic `app.dispatch` remains permissive.

## Work
- Add compile-only assertions in `src/__tests__/type-check.ts` before implementation for the planned client surface:
  - `app.client.dispatch("create-booking", validInput)` returns `Promise<Result<CreateBookingOutput, SliceError | CreateBookingError>>`.
  - `app.client.dispatch("get-pricing", validInput)` returns `Promise<Result<GetPricingOutput, SliceError | QueryError>>` or the query's concrete domain-error type if it is `never`.
  - `@ts-expect-error` for `app.client.dispatch("missing", {})`.
  - `@ts-expect-error` for missing or invalid typed input fields on a registered slice.
  - Existing `app.dispatch("anything", unknownInput)` remains accepted and returns `Promise<Result<unknown, unknown>>`.
  - Explicitly widened `AppConfig` behavior is covered or documented as intentional degradation.
- Update `src/core/app.ts` so `AppConfig`, `App`, and `createApp` preserve the configured slice tuple/literal information when callers pass a precise config.
- Add `AppClient` and operation lookup/input/output/error helper types in the cohesive owner chosen by implementation (`src/core/app.ts`, or a colocated `src/core/app-client.ts` if `app.ts` would become mixed-responsibility).
- Implement `client.dispatch(...)` by delegating to the existing local `dispatch` function; do not introduce a second runtime execution path or bypass schema validation.
- If a cast is unavoidable at the dynamic-to-typed boundary, keep it local to the app client construction, document why it is the app-client dynamic boundary, and avoid spreading casts into slice definitions or tests.
- Confirm `inputAdapter.bind(dispatch)` still receives the dynamic dispatch function, not the typed client method.
- Export the intended public `AppClient` and helper types from `src/index.ts`.
- Add one small runtime delegation assertion only if existing tests do not exercise `app.client.dispatch` at all; keep it narrow and avoid duplicating broad pipeline coverage.
- Run focused typecheck/test commands while iterating, then the required verification commands.

## Acceptance
- `createApp()` returns an app with `client.dispatch(...)` available for preserved slice tuples/literal names.
- `app.client.dispatch(...)` accepts registered command and query names and infers each slice's input, output, and error result types.
- Unknown typed-client slice names and invalid typed-client input shapes fail compile-only tests.
- Existing `app.dispatch(sliceName: string, input: unknown)` remains dynamic, source-compatible, and behavior-compatible for adapters and tests.
- The typed client delegates to the same dynamic dispatch path, so runtime parsing, command/query execution, event append, projection, processor, and side-effect behavior remain unchanged.
- Any dynamic-to-typed bridge cast is local, documented, and covered by type-check tests.
- Public exports include the intended typed app client types.
