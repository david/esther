# 03 — Clarify Fastify route input parse errors

## Source
- review/findings/01-fastify-route-parse-contract.md

## Goal

Make `llms.txt` Fastify route docs clear that `route.input(...)` runs before app dispatch. If route input parsing throws, Fastify host error handling owns that failure; Esther default result mapping only maps errors returned from dispatch.

## Depends on
- 02.md

- Source cross-checks in `src/adapters/fastify/input.ts`, `src/adapters/fastify/index.ts`, and `src/__tests__/type-check.ts`

## Contract surfaces
- Fastify route docs: request-to-operation `input` mapper executes before `boundDispatch(...)`
- Error docs: default Fastify result mapping covers `Result` errors such as `SchemaError`, not exceptions thrown by route input parsing
- Host responsibility docs: thrown route-input validation errors and authorization/session/token checks remain host/Fastify responsibilities
- Runtime/source behavior: none unless implementation deliberately chooses larger adapter behavior change from source finding
