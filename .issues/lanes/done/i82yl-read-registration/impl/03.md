# 03 — Register per-model query capability

## Source

## Goal

Back slice query reads and read-interpreter query descriptors with the per-model query capability from canonical and read-only registrations, while preserving legacy `projectionQuery` fallback and the existing missing-query behavior split.

## Contract surfaces
- read-model registration normalization: optional per-model `query` functions for writable registrations and read-only views
- `ProjectionStore.query` and `ProjectionStore.queryMany`: per-model query first, then legacy `projectionQuery`, then `ReadModelNotFound(sourceName, "query")`
- `ReadInterpreter` query descriptors: per-model query first, then legacy `projectionQuery`, then `[]` when no query capability exists
- legacy `projectionQuery` compatibility and query precedence

## Plan-check watch items
- Preserve exact missing-query split: `ProjectionStore` returns `ReadModelNotFound(sourceName, "query")`; `ReadInterpreter` returns `[]` when no per-model or legacy query exists.
- Normalize canonical and legacy registrations together and reject all duplicate names, including cross-kind and cross-config duplicates.
- Avoid new broad casts or `Record<string, unknown>` value types while erasing generic registration maps.

## Work
- Add or update a focused failing test showing a slice query/listing path works with `readModels: [createInMemoryProjectionAdapter(model)]` and no global `projectionQuery` wrapper.
- Add or update focused regression tests for missing query capability: slice query returns `ReadModelNotFound(sourceName, "query")`, while read-interpreter query descriptors return `[]` when neither per-model nor legacy query exists.
- Add or update a focused test for the chosen precedence rule: per-model query is used before legacy `projectionQuery` for the same source name.
- Extend normalization/app wiring to build a `projectionQueries` map from canonical writable registrations and read-only registrations that provide `query`.
- Update `ProjectionStore.query` and `queryMany` in `createApp()` to consult `projectionQueries` before legacy `config.projectionQuery` and to preserve current empty-result semantics.
- Update `getReadInterpreter()` to pass a `ProjectionQueryAdapter` wrapper over the same per-model query map, falling back to legacy `projectionQuery`, then returning `[]`.

## Acceptance
- Canonical in-memory read-model registrations support slice query and query-many reads without a global `projectionQuery` wrapper.
- Read-only registrations with `query` can provide per-view query capability without write capability.
- Legacy `projectionQuery`-only usage still works for query-handle tests that intentionally do not register a model.
- Per-model query capability takes precedence over legacy `projectionQuery` for the same source name.
- Slice missing-query behavior remains `ReadModelNotFound(sourceName, "query")`.
- Read-interpreter missing-query behavior remains an empty array.
