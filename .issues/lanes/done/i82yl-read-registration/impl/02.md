# 02 — Wire canonical in-memory registrations for writes and lookups

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Make the normal in-memory factory result app-ready for writable read-model registration and have `createApp({ readModels: [createInMemoryProjectionAdapter(model)] })` support projection writes, point lookups, derived constraint metadata, and automatic read-model event bindings without manual table entries.

- 01.md

## Scope
- `src/adapters/in-memory/read-model.ts`
- `src/core/read-model-registration.ts`
- `src/core/app.ts`
- read-model event binding tests in `src/__tests__/pipeline.test.ts` and/or `src/__tests__/pipeline-wiring.test.ts`
- in-memory adapter tests in `src/adapters/in-memory/read-model.test.ts`

## Contract surfaces
- adapter factory result shape: add `kind: "readModel"` and `handle` while preserving `adapter`, `get`, and `query`
- app wiring: canonical writable registrations populate projection write registry and point-lookup getter registry
- event-store constraint metadata: canonical writable registrations derive constraints from `handle.constraints` and table name from `handle.name`
- read-model event bindings: canonical writable registrations wire `handle.events` automatically

## Plan-check watch items
- Keep legacy table entries authoritative for their existing `constraints`/`tableName` behavior; derive metadata only for canonical writable registrations.
- Ensure postgres and in-memory factory return values remain destructurable and app-ready.
- Avoid new broad casts or `Record<string, unknown>` value types while erasing generic registration maps.

## Work
- Add or update a focused failing integration test showing `createApp({ readModels: [createInMemoryProjectionAdapter(model)] })` can write a projection through an emitted event and read it back through a slice projection lookup without manual `projectionAdapters`.
- Add or update a focused failing test proving read-model event bindings are wired from the canonical in-memory registration without manually passing `handle`.
- Add or update a focused failing test proving constraint metadata registration for canonical writable registrations uses `handle.name` and `handle.constraints`.
- Update the in-memory projection adapter result type and return value to include `kind: "readModel"` and `handle` without removing destructurable `adapter`, `get`, or `query`.
- Update `createApp()` to route normalized canonical writable registrations into `projectionAdapterRegistry`, `projectionGetters`, constraint metadata registration, and read-model event wiring.
- Preserve all legacy table-entry code paths and error behavior.
