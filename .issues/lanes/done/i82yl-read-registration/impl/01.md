# 01 — Add core read-model registration contract

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Introduce the canonical core registration type surface and normalization foundation that `createApp()` can consume without changing projection write/query behavior yet. Keep legacy `projectionAdapters` accepted and normalize canonical plus legacy names together so later tasks can wire behavior safely.

## Depends on
- none

## Scope
- `src/core/read-model-registration.ts` or an equivalent focused core module
- `src/core/app.ts`
- targeted app-wiring tests in `src/__tests__/pipeline.test.ts` or `src/__tests__/pipeline-wiring.test.ts`

## Contract surfaces
- public TypeScript API: `AppConfig.readModels`
- public/core types: `ProjectionGetter`, `ProjectionQuery`, `WritableReadModelRegistration`, `ReadOnlyReadModelRegistration`, `ReadModelRegistration`
- app-creation validation for duplicate registration names
- app-creation validation for canonical writable `adapter.name === handle.name`

## Plan-check watch items
- Keep the new registration normalization in a focused core module, not as more mixed responsibility in `src/core/app.ts`.
- Normalize canonical and legacy registrations together and reject all duplicate names, including cross-kind and cross-config duplicates.
- For canonical writable registrations, validate `registration.adapter.name === registration.handle.name` with a clear app-creation error.
- Avoid new broad casts or `Record<string, unknown>` value types while erasing generic registration maps.

## Work
- Add or update focused failing tests that construct minimal canonical writable/read-only registrations and assert duplicate-name and adapter/handle mismatch failures at app creation.
- Add the focused core registration module with the planned registration/query/getter types and a normalized internal shape suitable for app wiring.
- Extend `AppConfig` with optional `readModels` while keeping `projectionAdapters` and `projectionQuery`; mark legacy fields deprecated with JSDoc only.
- Have `createApp()` call the normalizer and use the normalized name list for duplicate detection while preserving existing legacy `projectionAdapters` behavior.
- Ensure legacy table/view entries still behave exactly as before in this slice.

## Acceptance
- `AppConfig` accepts a `readModels` array of canonical registration values at the type level.
- A focused normalization helper exists outside `src/core/app.ts` and is the single place that derives canonical/legacy registration names.
- Duplicate names across canonical writable registrations, canonical views, and legacy entries throw during app creation.
- Canonical writable registrations with mismatched adapter/handle names throw a clear app-creation error naming both sides.
- Existing legacy `projectionAdapters` tests continue to pass without behavior changes.

## Suggested tests
- Add focused tests in `src/__tests__/pipeline.test.ts` or `src/__tests__/pipeline-wiring.test.ts` for duplicate names across canonical/legacy registrations.
- Add a focused test for canonical writable adapter/handle mismatch.
- Prefer minimal fixtures and real framework primitives over mocks.
