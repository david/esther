# 04 — Make postgres factory registrations app-ready

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Give the postgres projection adapter factory the same app-ready writable registration shape as the in-memory factory while preserving its existing DDL, write, get, query, and direct replay/test helper usage.

## Depends on
- 03.md

## Scope
- `src/adapters/postgres/read-model.ts`
- postgres adapter tests, likely `src/adapters/postgres/read-model.test.ts`
- any postgres-related public re-export file if the adapter has one

## Contract surfaces
- adapter factory result shape: add `kind: "readModel"` and `handle` while preserving `adapter`, `get`, and `query`
- postgres DDL generation remains unchanged
- postgres projection writes, point lookups, and query translation remain unchanged
- direct destructuring and replay-style `adapter.execute()` usage remains valid

## Plan-check watch items
- Ensure postgres and in-memory factory return values remain destructurable and app-ready.
- Keep legacy table entries authoritative for their existing `constraints`/`tableName` behavior; derive metadata only for canonical writable registrations.
- Avoid new broad casts or `Record<string, unknown>` value types while erasing generic registration maps.

## Work
- Add or update a focused failing postgres adapter test asserting the factory result includes `kind: "readModel"`, the original `handle`, `adapter`, `get`, and `query`.
- Add or update focused regression coverage, if missing, that direct destructuring and `adapter.execute()` usage still works after the return shape change.
- Update the postgres projection adapter result type and returned value to implement the writable read-model registration contract.
- Verify `generateCreateTableDDL(handle)` output and postgres query/write behavior are unchanged except for the extra factory result fields.
- Do not introduce core imports into postgres code beyond core type imports already allowed for adapters.

## Acceptance
- Postgres factory results include `kind: "readModel"`, `handle`, `adapter`, `get`, and `query`.
- Existing postgres adapter write/get/query behavior remains unchanged.
- Existing DDL generation remains unchanged; no migration/backfill/replay change is introduced.
- Direct `const { adapter, get, query } = createPostgresProjectionAdapter(sql, handle)` usage remains type-safe and runtime-compatible.
- No adapter-to-adapter or core-to-adapter dependency boundary violations are introduced.
