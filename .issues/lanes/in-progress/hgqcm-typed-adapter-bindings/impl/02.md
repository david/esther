# 02 — Add typed Fastify route binding contracts

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Expose a typed Fastify route configuration helper that correlates each route's `slice` literal with that route's input mapper and optional response mapper types, while keeping the adapter-to-core dispatch boundary dynamic.

## Depends on
- 01.md

## Scope
- `src/adapters/fastify/input.ts` or a small colocated route contract module such as `src/adapters/fastify/routes.ts`
- `src/adapters/fastify/index.ts`
- `src/index.ts` if Fastify route helpers are part of the public root API
- `src/__tests__/type-check.ts`

## Contract surfaces
- `FastifyAdapterConfig` additive `routes?` field
- New `FastifyRouteMethod`, `FastifyRouteRequest`, `FastifyRouteBinding`, and `defineFastifyRoutes` contracts or equivalent names
- Fastify-specific request/reply types remain inside the Fastify adapter surface
- Optional typed `respond` callback receives the selected operation `Result` type
- No runtime route execution behavior is required by this task beyond accepting the config shape

## Plan-check watch items
- Ensure each route object's `slice` literal is correlated with that same route's `input` and optional `respond` callback types; use a mapped-union or builder design if a default union permits mismatches.
- Do not silently drop optional typed `respond` support; include it here at the type-contract level or stop and ask to split the feature.
- Keep route typing explicitly tied to the preserved slice tuple passed to `defineFastifyRoutes<typeof slices>()`.
- Watch exact optional property types for `routes?`, `hostname?`, and `respond?`.

## Work
- Add compile-only route examples in `src/__tests__/type-check.ts` first using the command/query tuple from task 01.
- Cover accepted routes for known command and query slice names, with mapper return values matching each selected slice input type.
- Add `@ts-expect-error` coverage for an unknown `slice` name and for command/query route input mappers returning the other slice's input shape.
- Add type assertions that optional `respond` receives `Result<SelectedOutput, SliceError | SelectedDomainError>` for the selected command/query.
- Implement the typed Fastify route contracts and `defineFastifyRoutes` helper with no core-to-adapter dependency.
- Add `routes?` to the Fastify config type as an additive optional field without changing existing `port` and `hostname` usage.
- Export the new helper/types from the Fastify adapter entrypoint and, if consistent with existing public API policy, the package root.

## Acceptance
- `defineFastifyRoutes<typeof slices>()([...])` accepts routes for known command and query slice names.
- The route `input` mapper return type is checked against the selected slice input, not just the union of all inputs.
- The optional `respond` callback is typed with the selected slice result.
- Unknown slice names and mismatched mapper return shapes fail in compile-only tests.
- Existing `createFastifyInputAdapter({ port, hostname })` usage remains source-compatible.
