## Drift assessment
- Aligned with `impl/04.md`, `plan/01-implementation-plan.md`, and `plan/checks/01-plan-sanity.md`.
- Optional `respond` is opt-in and only runs for explicit routes that configure it; explicit routes without `respond` and wildcard dispatch still use the shared default result mapper.
- The `respond` context includes the selected dispatch `Result`, the same request context shape as the input mapper, and `FastifyReply`.
- Runtime validation remains owned by core dispatch; existing explicit-route `SchemaError` default mapping coverage remains in place.
- No public `app.client`, `app.execute`, typed in-process dispatch facade, or narrowed `App.dispatch` / `DispatchFn` / `InputAdapterBinding.bind` API was added.
- The runtime callback bridge uses a local function guard and no casts; core, event stores, read models, processors, and effect adapters were not changed.
