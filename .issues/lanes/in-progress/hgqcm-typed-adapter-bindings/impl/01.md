# 01 — Add operation name and result type helpers

## Source
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md

## Goal

Establish the core type-level contract that lets adapter helpers map a preserved slice tuple and slice name to the selected command/query input, output, error, and `Result` types without changing runtime dispatch.

## Depends on
- none

## Scope
- `src/core/slice.ts` or a cohesive colocated core type-only module such as `src/core/slice-types.ts`
- `src/index.ts`
- `src/__tests__/type-check.ts`
- Existing dynamic app/input-adapter signatures only as compatibility checks; do not change them

## Contract surfaces
- TypeScript-only core slice contracts: `RegisterableOperation`, `Command`, `Query`, `defineCommand`, `defineQuery`
- New operation lookup helpers such as `OperationName`, `OperationByName`, `OperationInput`, `OperationOutput`, `OperationError`, and `OperationResult`
- Public root exports for the helper types if they are intended as package API
- No runtime events, schemas, persistence, read-model behavior, processors, or side effects

## Plan-check watch items
- Preserve literal command and query names where TypeScript can infer them.
- Keep route/helper precision tied to preserved slice tuples; widened `ReadonlyArray<RegisterableOperation>` must not imply false precision.
- Keep casts local and documented if unavoidable.

## Work
- Add compile-only assertions in `src/__tests__/type-check.ts` first for literal command/query names, tuple-derived `OperationName`, input/output/error/result extraction for one command and one query, and the widened-array degradation case.
- Update core operation types so command and query definitions can preserve inferred literal `name` values while keeping existing explicit generic call sites source-compatible.
- Add operation helper types that work for both commands and queries and produce `Result<Output, SliceError | DomainError>` for selected operations.
- Export the new helper types from the intended public surface without adding adapter imports to core.
- Add compatibility assertions that `App.dispatch("anything", unknownInput)` still type-checks as `Promise<Result<unknown, unknown>>` and `DispatchFn` remains dynamic.
- Run the focused typecheck and adjust only this contract surface until the new type assertions pass.

## Acceptance
- Inferred named `defineCommand` and `defineQuery` declarations preserve literal `name` types.
- `OperationName<typeof slices>` is the union of names from a preserved command/query tuple.
- `OperationByName`, `OperationInput`, `OperationOutput`, `OperationError`, and `OperationResult` select the correct command and query types.
- Dynamic `App.dispatch` and `DispatchFn` signatures remain string/unknown runtime boundaries.
- Widened slice arrays are documented by type assertions as less precise rather than falsely narrowed.
