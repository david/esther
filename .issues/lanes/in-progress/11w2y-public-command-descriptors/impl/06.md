# 06 — Support overload-reusing command definition wrappers

## Source
- review/findings/02-direct-wrapper-inline-inference.md
- plan/01-implementation-plan.md
- plan/checks/01-plan-sanity.md
- current conversation decision: `commandDefinition({...})` is acceptable as the inference anchor, but extensions like `authenticated(...)` add behavior and should not have to copy private overload shapes.

## Goal

Support extension-authored command descriptor wrappers that add behavior (for example `authenticated(...)`) while still accepting direct inline definition-backed descriptors with unannotated callbacks.

Do not try to make this impossible shape work by type-alias magic alone:

```ts
function wrap<T extends AnyCommandDefinition>(definition: T): T {
  return commandDefinition(definition);
}
```

TypeScript does not use the function body to contextually type the inline object. Instead, expose a public wrapper-author API that reuses Esther-owned `commandDefinition(...)` overloads at the function users call.

Preferred API direction unless implementation proves a better name/pattern:

```ts
const authenticated = commandDefinitionWrapper((definition) => {
  return commandDefinition({
    ...definition,
    // extension behavior here, such as adding validation or metadata
  });
});

authenticated({
  input: compose<CreateInput>(),
  event: Created,
  tags: (ctx) => [`tenant:${ctx.tenantId}`],
  payload: (ctx) => ({ tenantId: ctx.tenantId }),
  output: (event, ctx) => ok({ id: event.payload.id }),
});
```

If exact behavior-changing transforms cannot preserve descriptor type safely for all families, implement the narrowest safe public helper and document the supported wrapper pattern explicitly.

## Acceptance
- Extension wrapper created through public wrapper-author API accepts a direct inline definition-backed descriptor without callback parameter annotations.
- Direct wrapper inference exposes composed input enrichment in `validate`, `tags`, `payload`, and `output` callback `ctx`.
- Direct wrapper `payload(ctx)` uses schema-input candidate type and `output(event, ctx)` receives parsed `EventOf<typeof Event>`.
- `defineCommand(authenticated({ ...bad payload... }))` fails for invalid definition-backed payload fields/types.
- Wrapper returns an exact descriptor type or another safe public descriptor type usable by `defineCommand`.
- Extension authors do not need private shape copies or `unknown` casts for the supported wrapper pattern.
- `commandDefinition(...)` remains runtime identity with no validation, cloning, or normalization.
- Raw-event command descriptor behavior remains unchanged.
- `llms.txt` documents the supported wrapper pattern and the limitation of plain `T extends AnyCommandDefinition` direct inline wrappers.
