# 02 — Prove public type inference through reducer and command paths

## Source
- plan/01-implementation-plan.md

## Goal
Prove `defineEvent(...)` removes duplicated event and payload types while preserving reducer narrowing and command event return typing through package-root imports.

## Depends on
- 01.md

## Scope
- `src/__tests__/type-check.ts`
- `src/core/event.ts` if type refinements are needed
- `src/index.ts` if root type exports need correction

## Contract surfaces
- public type aliases: `EventOf`, `EventPayloadOf`, `EventDefinition`
- command `event(ctx)` return typing with `EventOf<typeof Event>`
- reducer schema union inference from `[Event.schema] as const`
- package root import surface

## Plan-check watch items
- Keep direct `EventDefinition` acceptance in reducer/read-model/processor APIs out of this slice; users must pass `.schema`.
- Add root-import type tests proving public API, not only relative module imports.
- If `schema` typing needs a cast, keep it as narrow as possible inside `src/core/event.ts` and document why.
- Verify `.create(...)` copies `tags` and keeps payload reference caller-owned.

## Work
- Add focused failing type-check cases in `src/__tests__/type-check.ts` using package-root imports for `defineEvent`, `EventDefinition`, `EventOf`, and `EventPayloadOf`.
- Prove `defineEvent({ type, payload })` preserves the event type literal.
- Prove `EventOf<typeof BookingCreated>` matches `DomainEvent<"BookingCreated", z.output<typeof payloadSchema>>`.
- Prove `EventPayloadOf<typeof BookingCreated>` equals payload schema output.
- Prove `.create(...)` requires payload fields and rejects mismatched payload types with `@ts-expect-error` assertions.
- Prove a command `event(ctx)` can return `BookingCreated.create(...)` when command event type is `EventOf<typeof BookingCreated>`.
- Prove `defineReducer({ schemas: [BookingCreated.schema] as const })` narrows `event` on `event.type` and exposes typed payload fields.
- Make smallest production type refinements needed to satisfy these tests without changing reducer/command APIs to accept event definitions directly.

## Acceptance
- Public root imports support `defineEvent`, `EventDefinition`, `EventOf`, and `EventPayloadOf` in type-check coverage.
- Event type and payload types derive from Zod payload schema output, not duplicate handwritten interfaces.
- `.create(...)` has typed payload input and rejects mismatches at compile time.
- Command event callbacks can return `Event.create(...)` with `EventOf<typeof Event>` event type.
- Reducer event parameter narrows correctly when schemas come from event definitions.
- Reducer API still takes schemas; passing whole event definitions is not introduced.
