# 01 — Accept required-outputErr command descriptors

## Source
- plan/01-implementation-plan.md

## Goal

Make `DefinitionBackedCommandDefinitionWithOutputErr` a first-class public definition-backed command descriptor for `commandDefinition(...)` and `defineCommand(...)`, so generic authenticated wrappers can pass required-`outputErr` descriptors without downstream `as unknown as ...` casts while preserving definition-backed event typing.

## Depends on
- none

## Scope
- `src/core/slice.ts` command descriptor overloads and any narrow runtime-compatible type signature needed for overload implementation compatibility
- `src/__tests__/type-check.ts` CMS-shaped generic wrapper fixture
- `src/index.ts` export check only if implementation finds missing public exports
- `llms.txt` public command wrapper guidance, or checkpointed no-update reason

## Contract surfaces
- TypeScript API: `commandDefinition(...)` identity overload for `DefinitionBackedCommandDefinitionWithOutputErr`
- TypeScript API: named `defineCommand(...)` overload preserving `TName`
- TypeScript API: unnamed `defineCommand(...)` overload returning `string` name
- Event typing: preserve `EventOf<TEventDefinition>` output input and `EventCandidateOf<TEventDefinition>` command event candidate
- Runtime command pipeline: unchanged; no new execution semantics, I/O, adapter behavior, event schema bypass, persistence, replay, read model, or processor change

## Intent / decision vocabulary
- `acceptRequiredOutputErrDescriptor`: required-`outputErr` definition-backed descriptors are accepted directly by public helpers
- `preserveNamedCommandIdentity`: `{ readonly name: TName }` flows into returned `Command` name type
- `preserveDefinitionBackedEventContract`: event definition stays schema-backed; no raw-event downgrade
- `descriptorIdentityForWrappers`: `commandDefinition(descriptor)` preserves wrapper descriptor shape, including literal name intersections when present
- `conditionalOutputErrBypass`: required-outputErr overloads appear before conditional `DefinitionBackedCommandDefinition` overloads so generic widened error unions avoid `CommandOutputErrDefinition`

## Acceptance
- `commandDefinition(...)` accepts a `DefinitionBackedCommandDefinitionWithOutputErr` descriptor and preserves its exact wrapper descriptor type, including literal name intersections when present.
- `defineCommand(...)` accepts named and unnamed `DefinitionBackedCommandDefinitionWithOutputErr` descriptors.
- Named overload returns `Command<..., TName, EventCandidateOf<TEventDefinition>>`; unnamed overload returns `Command<..., string, EventCandidateOf<TEventDefinition>>`.
- CMS-shaped generic descriptor with widened `AuthenticatedSessionError | TError` compiles through both helper calls without downstream-style `as unknown as ...`.
- Definition-backed event candidate/output typing remains intact.
- Runtime behavior remains unchanged; no event, replay, read model, adapter, processor, persistence, or auth policy change lands.
- `llms.txt` is updated for direct required-outputErr descriptor acceptance, or checkpoint records why existing guidance was already current.
