## Work
- Add focused failing command-pipeline tests for `tagQuery(...)`:
  - a command whose input uses `compose().add(tagQuery(...))` and writes to the same tag returns `ConcurrencyError` when an `EventStore` wrapper inserts a matching event between `queryByTags(...)` and append.
  - the same stale path is covered when the observed boundary is empty (`maxPosition === undefined`).
- Add a focused failing multi-observation test using two command-side event-history descriptors.
  - Assert the dispatch returns `BoundaryObservationError` with both copied observations.
  - Assert validation, `event`, append, success output, projectors, processors, and effects do not run.
- Add or update public type-level coverage for the exported observation/error surfaces if inference or exports are affected.
- Add `BoundaryObservation` and `BoundaryObservationError` types plus a constructor in `src/core/types.ts`; include the error in `SliceError`.
- Export the new public surfaces from `src/index.ts`.
- Extend `SliceDeps` with optional `recordBoundaryObservation?: (observation: BoundaryObservation) => void`.
- Extend command `PipelineDeps` so `InputPipeline.execute(...)` can receive the optional observation sink.
- Update command-side `tagQuery(...).toStep(...)` to copy the queried tags, call `queryByTags(...)`, and record `{ tags, maxPosition }` when the sink exists.
- Keep query-state `state().pipe(tagQuery(...))` read-only by not passing an observation sink in query resolution.
- Update `executeCommand(...)` to collect observations during input resolution.
- After successful input resolution and before validation/event/append/output success:
  - zero observations: append exactly as today with no options.
  - one observation: append with copied `{ boundaryTags: observation.tags, expectedPosition: observation.maxPosition }`.
  - more than one observation: return `BoundaryObservationError` directly.
- Update framework-error recognition for `_tag === "BoundaryObservationError"` for consistency.
- Preserve `outputErr` routing for domain/input descriptor errors.

## Acceptance
- Command-side `tagQuery(...)` records the exact queried tags and returned `maxPosition`, with tag arrays copied at observation time.
- A command with one `tagQuery(...)` observation appends with matching `boundaryTags` and `expectedPosition`.
- A stale concurrent write on that boundary returns `ConcurrencyError` and does not append the command event.
- Empty observed boundaries are protected by passing `expectedPosition: undefined` in present append options.
- Commands with no event-history observations append as before.
- Commands with multiple observations return exported `BoundaryObservationError` before validation, event construction, append, success output, projectors, processors, or effects.
- Domain/input descriptor errors still route through `outputErr`.
- Query-slice `state().pipe(tagQuery(...))` does not record observations or derive append preconditions.
