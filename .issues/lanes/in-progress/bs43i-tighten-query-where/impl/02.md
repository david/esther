# 02 — Validate queryDescriptor where clauses at runtime

## Source
- plan/02-implementation-plan.md
- plan/checks/02-plan-sanity.md

## Goal
Make `queryDescriptor({ model, where })` use schema-aware runtime validation so unsafe-cast unsupported filters throw synchronously instead of being dropped or reaching adapters.

## Depends on
- 01.md

## Scope
- `src/core/read-model.ts`
- `src/core/read-model.test.ts`

## Contract surfaces
- runtime descriptor constructor: `queryDescriptor(...)`
- runtime adapter contract producer: `normalizeWhere(...)` or replacement helper
- read-model schema metadata: `ReadModelHandle.schema.shape[field]`
- error surface: thrown `Error` with read model name, field, and reason

## Plan-check watch items
- Preserve `undefined` field-entry skipping for conditional filter construction.
- Avoid `Record<string, unknown>` and bare `object`; use `unknown` guards or named local shapes.
- Keep implementation core-only; no core imports from adapters.
- Use existing `getZodTypeName(...)` only through core-local dependency as planned.
- Preserve `defineReadModel` support for `ZodArray`/`ZodObject`; only `where` support narrows.
- Assert error substrings that prove read model/query name, field, and reason without overfitting whole messages.

## Work
- Add focused runtime tests in `src/core/read-model.test.ts` for `queryDescriptor(...)` before implementation:
  - valid equality/range/`in` entries for `ZodString`, `ZodNumber`, and `ZodBoolean` fields stay unchanged.
  - `undefined` field entries are skipped.
  - unsafe unknown field throws before adapter query.
  - unsafe array/object field equality with primitive value throws.
  - unsafe array/object field `in` with primitive array throws.
  - unsafe object/array range with primitive value throws.
  - unsafe boolean range throws.
  - unsafe wrong primitive kind for schema field throws, including string field `in` with numbers.
  - unsafe non-primitive `in` values throw.
- Change runtime normalization to accept the read model handle or model name plus schema shape.
- Validate field exists in `model.schema.shape` before emitting any `WhereEntry`.
- Validate Zod field kind before operator/value handling:
  - `ZodString`: equality, range, `in` with strings.
  - `ZodNumber`: equality, range, `in` with numbers.
  - `ZodBoolean`: equality and `in` with booleans only; no range.
  - `ZodArray` / `ZodObject` / unsupported kinds: no `where` operators.
- Throw explicit errors for every non-`undefined` unsupported descriptor shape; do not silently drop clauses.
- Update `queryDescriptor(...)` to call this schema-aware path.
- Preserve `WhereEntry` output shape for valid descriptors.

## Acceptance
- `queryDescriptor(...)` emits same `WhereEntry[]` for valid primitive filters as before.
- `queryDescriptor(...)` throws for unknown fields before adapter query.
- `queryDescriptor(...)` throws for object/array fields even when unsafe casts provide primitive-shaped clauses.
- `queryDescriptor(...)` throws for boolean ranges, non-primitive `in` values, and wrong primitive kinds for schema fields.
- `where: { field: undefined }` remains skipped.
- No adapter code changes are needed for this slice.
