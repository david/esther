# 01 — Tighten public where type grammar

## Source
- plan/02-implementation-plan.md
- plan/checks/02-plan-sanity.md

## Goal
Make unsupported `where` clauses fail at compile time through public `Where<T>` / `WhereClause<V>` types, while preserving valid primitive query grammar and read-model storage support for arrays/objects.

## Depends on
- none

## Scope
- `src/core/read-model.ts`
- `src/__tests__/type-check.ts`
- `llms.txt` read-model query grammar section

## Contract surfaces
- public TypeScript DSL: `Where<T>`, `WhereClause<V>`, `WhereRange<V>`, `WhereIn<V>`
- read-model query docs in `llms.txt`

## Plan-check watch items
- Keep `WhereClause` helper behavior stable for literal string/number/boolean fields and avoid distributive conditional leaks for unions.
- Avoid `Record<string, unknown>` and bare `object`; use `unknown` guards or named local shapes.
- Preserve `defineReadModel` support for `ZodArray`/`ZodObject`; only `where` support narrows.
- Update `llms.txt` so object/array fields are documented as storage-only for `where`.

## Work
- Add or update compile-only assertions in `src/__tests__/type-check.ts` first:
  - positive: string equality/range/`in`, number equality/range/`in`, boolean equality/`in`, literal string/number/boolean fields.
  - negative with `@ts-expect-error`: object equality, array equality, object/array `in`, object/array range, boolean range.
- Tighten `WhereRange<V>` to string/number range values only.
- Tighten `WhereIn<V>` to string/number/boolean values only.
- Change `WhereClause<V>` so:
  - string/number fields allow equality, range, and `in`.
  - boolean fields allow equality and `in` only.
  - object/array/unsupported fields produce no clause.
- Change `Where<T>` so non-queryable keys are omitted from accepted `where` object type.
- Keep `WhereEntry` runtime shape unchanged.
- Update `llms.txt` read-model query grammar to document primitive-only `where`: string/number/boolean equality, string/number range, string/number/boolean `in`, object/array fields storage-only for `where`.

## Acceptance
- Invalid object/array `where` clauses do not type-check.
- Boolean range clauses do not type-check.
- Valid string/number/boolean clauses still type-check, including literal field values.
- `defineReadModel` still accepts `z.array(...)` and `z.object(...)` schema fields for storage/projection.
- `WhereEntry` adapter contract shape remains unchanged.
- `llms.txt` documents primitive-only `where` grammar and object/array non-queryability.
