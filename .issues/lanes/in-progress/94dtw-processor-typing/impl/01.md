# 01 — Preserve descriptor result type and validate interpreter rows

## Source
- plan/01-implementation-plan.md

## Goal

Make `ReadInterpreter.resolve(...)` preserve `ReadDescriptor<T>` as `Promise<T>` and validate read-model `get`/`query` rows before returning them to handler wiring.

## Depends on
- none

## Scope
- `src/core/read-interpreter.ts`
- `src/core/read-interpreter.test.ts`
- `src/core/slice.ts`
- new colocated core validation helper, likely `src/core/read-model-validation.ts`
- `src/core/types.ts` imports/usages only if needed for existing `ReadModelSchemaError`

## Contract surfaces
- Internal core API: `ReadInterpreter.resolve` return type changes from `Promise<unknown>` to `Promise<T>`.
- Read-model descriptor runtime boundary: `getDescriptor(...)` found rows and `queryDescriptor(...)` rows become schema-validated.
- Error contract: reuse existing `ReadModelSchemaError` shape.
- Persistence/events/adapters: none changed.

## Plan-check watch items
- Keep validation helper cast local and documented.
- Preserve existing `ReadModelSchemaError` messages and `queryName` behavior for slice projection reads.
- Interpreter tests are minimum owner tests for malformed `get`/`query` rejection.
- Do not change event payloads, storage format, adapter boundaries, query fallback, or missing-row behavior.

## Work
- Add or update focused tests in `src/core/read-interpreter.test.ts` first:
  - `resolve(getDescriptor(...))` result is used as typed row or `undefined` without manual `unknown` extraction.
  - `resolve(queryDescriptor(...))` result is used as typed readonly rows without manual `unknown` extraction.
  - malformed `get` row rejects with `ReadModelSchemaError`.
  - malformed `query` row rejects with `ReadModelSchemaError`.
  - missing `get` still resolves `undefined` and existing `eventsByTagsDescriptor(...)` behavior remains unchanged.
- Extract existing slice read-model row validation into a colocated core helper, preferring `validateReadModelRow(...)` and `validateReadModelRows(...)`.
- Update `src/core/slice.ts` to use the helper so slice and interpreter validation behavior stay aligned.
- Change `ReadInterpreter.resolve` type to `<T>(descriptor: ReadDescriptor<T>) => Promise<T>`.
- In `src/core/read-interpreter.ts`, validate `getDescriptor(...)` hits and every `queryDescriptor(...)` row through descriptor model schema before resolving.
- Preserve query capability selection/fallback behavior: per-model query, deprecated `projectionQuery`, then `[]`.
- Keep any unavoidable cast inside the validation helper with a short comment explaining `ReadModelHandle` schema output and descriptor generic equivalence.

## Acceptance
- `ReadInterpreter.resolve` returns `Promise<T>` for `ReadDescriptor<T>`.
- Valid `getDescriptor(...)` hit returns parsed row; missing row still returns `undefined`.
- Valid `queryDescriptor(...)` returns parsed rows; missing query capability fallback remains `[]`.
- Malformed `get` and `query` rows reject with `ReadModelSchemaError` before handler code can consume them.
- Slice read-model validation behavior and diagnostics do not regress.
- No event payload, storage, or adapter contract changes.
